# V1 Milestone Plan

This plan keeps the V1 focused: homepage, one flagship case study, and one strong project inquiry experience.

## Milestone 00 - Studio Foundation

Status: complete.

Goals:

- Inspect repository state.
- Establish the smallest sensible frontend foundation.
- Create canonical product/business/design brief.
- Create project README.
- Establish source architecture for pages, layout, shared components, styles, content, and assets.
- Add baseline engineering safeguards only where useful for the scaffold.
- Confirm the scaffold builds.

Out of scope:

- Homepage design/implementation.
- Rangers Legends case study build.
- Start a Project form.
- Speculative animation.
- Rangers Legends asset import.
- Deployment or GitHub push.

## Milestone 01 - Visual System Foundation

Status: complete after Milestone 01 approval.

Define the CWT base system before building pages.

- Establish approved base tokens for ink, paper, muted neutrals, spacing, layout, focus, and motion preferences.
- Decide typography direction without downloading fonts unless approved.
- Define grid behavior for desktop/tablet/mobile.
- Define project accent strategy.
- Create small reusable primitives only as needed.
- Validate responsive containment rules early.

## Milestone 02 - Global Shell and Navigation

Create the route-aware frame around the site.

- Implement global layout.
- Add accessible navigation.
- Add footer/CTA shell if approved.
- Add route metadata helper architecture.
- Verify keyboard navigation and visible focus states.

## Milestone 03 - Homepage Content Architecture

Build the homepage narrative in neutral CWT system.

- Implement positioning sequence.
- Introduce Rangers Legends as featured proof without overbuilding the case study.
- Add simplified method: Find, Define, Build, Grow.
- Add three ways to work together.
- Add final start-a-project CTA.
- Keep claims factual and restrained.

## Milestone 04 - Rangers Legends Case Study Foundation

Create the case study page structure and content model.

- Establish concept-framing language.
- Add case study metadata and disclaimers.
- Define narrative acts.
- Link to external Rangers Legends experience.
- Avoid rebuilding Rangers Legends inside CWT.

## Milestone 05 - Rangers Legends Narrative Sections

Build the case study as an unfolding argument.

- Implement Hook, Opportunity, Story, World, System, Value, Expansion, CWT, and Final Act.
- Show READ / WATCH / EXPLORE / SHARE / WEAR / COLLECT as connected expressions.
- Keep commercial opportunities framed as possibilities, not outcomes.

## Milestone 06 - Case Study Interaction and Polish

Add meaningful progressive enhancement.

- Use motion to reveal, transform, and connect.
- Add no hover-only critical functionality.
- Respect reduced-motion preferences.
- Avoid complex 3D/shaders/custom scroll engines unless later approved.

## Milestone 07 - Start a Project

Create the inquiry experience deliberately.

- Confirm fields, tone, and qualification flow.
- Decide no-backend vs. form service vs. custom integration.
- Build accessible form states.
- Avoid intimidating enterprise procurement patterns.

## Milestone 08 - Responsive and Accessibility Review

Test the full V1 across target widths.

- Review 1440, 1024, 768, 430, and 390.
- Check keyboard flows, focus visibility, landmarks, headings, reduced motion, and form usability.
- Fix containment and overflow issues at source.

## Milestone 09 - Performance and Media

Prepare production media responsibly.

- Define responsive image strategy.
- Optimize hero/critical assets.
- Lazy-load non-critical media.
- Review bundle size and dependencies.
- Avoid unnecessary animation libraries.

## Milestone 10 - SEO and Shareability

Prepare route-level metadata.

- Add default metadata.
- Add Open Graph and Twitter/X preview strategy.
- Add canonical URL after deployment origin is known.
- Add favicon/social image only when approved assets exist.

## Milestone 11 - Deployment

Ship the small V1 cleanly.

- Confirm hosting target.
- Validate SPA routing behavior.
- Run production build and preview.
- Deploy only after approval.

## Milestone 12 - Final QA

Do a launch-readiness pass.

- Check copy accuracy and content safeguards.
- Test routes and not-found state.
- Test external links.
- Confirm no invented claims.
- Confirm mobile and desktop experience.
